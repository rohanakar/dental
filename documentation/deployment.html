Deployment & operations

DentalCAD runs as three Docker Compose services on a single OCI VM (aarch64, 12 vCPU, 6 GB RAM) and is served at https://dental.cognifuze.com. This page covers how the pieces fit, how to deploy and verify, and how to move the stack elsewhere later.

In short
  • Three containers: proxy (Caddy + the built web app), api (Node 22 + Hono) and db (Postgres 17). They build natively on the ARM64 VM. Built · Day 1
  • Nginx Proxy Manager (NPM) on the VM owns dental.cognifuze.com and TLS. Our proxy joins the external Docker network shared_net as dcad-proxy and serves plain HTTP on :80. No service publishes a host port.
  • One .env at the repo root holds all config and secrets. On the VM it is created by hand and never committed.
  • Deploy on the VM with git pull && ./infra/compose.sh up -d --build. The repo is private (git@github.com:rohanakar/dental.git), cloned with a read-only deploy key. Migrations run automatically on API start.
  • Backups are manual today. The backup container is planned for Day 5. Planned · Day 5

Compose services

Memory budget: the limits add up to about 2.6 GB of the VM's 6 GB, leaving roughly 3 GB for the OS, NPM and a future CPU inference container. The VM has no GPU, so future ml.* proposers will run on a separate GPU host (see AI assist).

ARM64The VM is aarch64. node:22-slim, postgres:17 and caddy:2 are all multi-arch, so compose up --build on the VM produces native linux/arm64 images, with no emulation. To build elsewhere for the VM, use docker buildx build --platform linux/arm64 …. The Day 1 stack was built and run on an arm64 Mac, the same architecture.
Deeper detail: Caddy routing (infra/Caddyfile)
  • Site address :80: plain HTTP only. Nginx Proxy Manager in front handles the domain and TLS.
  • handle_path {$BASE_PATH}/* strips the sub-path (empty at the root), so the API always sees /api/* and the SPA files sit at the root of /srv. Anything outside the base path gets 404.
  • /api/* goes to reverse_proxy api:3000 with flush_interval -1, so scan streams are not buffered.
  • Everything else is a static file with try_files {path} /index.html for client-side routing. /assets/* gets Cache-Control: public, max-age=31536000, immutable (hashed file names); HTML gets no-cache.

Configuration: the .env

One gitignored file at the repo root, started from .env.example. Locally it is used by pnpm dev:api. On the VM it is used by infra/compose.sh, both for Compose variable interpolation and as the api container's environment. Empty values count as unset. Don't put comments on the same line as a value.

KeyProduction valueNotes
PUBLIC_URLhttps://dental.cognifuze.comMust match what the browser uses (the domain NPM serves)
POSTGRES_PASSWORDopenssl rand -hex 24Hex only: it is embedded in DATABASE_URL
AUTH_SECRETopenssl rand -base64 48At least 32 characters
ANTHROPIC_API_KEY and/or OPENAI_API_KEYyour key(s)Anthropic is preferred if both are set. Neither means the offline mock.

Every other key is optional, with defaults in apps/api/src/config.ts. They are listed in the Backend API configuration reference.

Fill the secrets before the first up.env.example ships POSTGRES_PASSWORD and AUTH_SECRET empty. An empty POSTGRES_PASSWORD stops Postgres from starting, and an AUTH_SECRET under 32 characters stops the API. Postgres keeps the password it was initialized with: changing it later requires ALTER USER inside the database, not just editing .env.

Script: compose.sh

infra/compose.sh does one thing: it changes to the repo root and runs exec docker compose --env-file .env -f infra/docker-compose.yml "$@". Extra -f overrides (e.g. infra/docker-compose.dev.yml) pass straight through. There is no deploy script: the VM pulls from git.

Migrations

With MIGRATE_ON_START=true (the default), the API applies the Drizzle migrations in /app/drizzle before it starts listening, so a deploy that changes the schema needs no extra step. Manual run: ./infra/compose.sh exec api node dist/migrate.js.

First deployment checklist

  1. DNS: create an A record dental.cognifuze.com → the VM's public IP.
  2. VM prerequisites: Docker Engine with Compose v2.24+ (docker compose version). Create the shared network once with docker network create shared_net, and attach NPM to it (shared_net as an external network in NPM's compose file).
  3. Code: create a read-only deploy key and clone: 
    ssh-keygen -t ed25519 -f ~/.ssh/dcad_deploy -N ""   # add the .pub under the repo's Settings → Deploy keys
GIT_SSH_COMMAND="ssh -i ~/.ssh/dcad_deploy" git clone git@github.com:rohanakar/dental.git ~/dcad
git -C ~/dcad config core.sshCommand "ssh -i ~/.ssh/dcad_deploy"
  4. Create the .env: cd ~/dcad && cp .env.example .env, then set PUBLIC_URL, POSTGRES_PASSWORD, AUTH_SECRET, and your LLM key.
  5. Start: ./infra/compose.sh up -d --build, then ./infra/compose.sh ps. All three services should show as running, with api and db healthy.
  6. Check from the VM: docker run --rm --network shared_net curlimages/curl -s http://dcad-proxy/api/healthz → {"ok":true}.
  7. NPM proxy host: domain dental.cognifuze.com, scheme http, forward host dcad-proxy, port 80, Websockets Support on. On the SSL tab request a Let's Encrypt certificate and enable Force SSL. Add the Advanced snippet below.
  8. Firewall: only 80/443 (owned by NPM) need to be open in the OCI security list / NSG.
  9. Run the post-deploy verification below.
NPM proxy host: Advanced tab 
# Scans are large; the API enforces MAX_UPLOAD_BYTES (default 200 MB) itself.
client_max_body_size 250m;
# Stream scan uploads/downloads instead of spooling them to disk
proxy_request_buffering off;
proxy_buffering off;
proxy_read_timeout 300s;
proxy_send_timeout 300s;

The same snippet lives in infra/README.md.

Post-deploy verification

These are the same ten checks that passed in the Day 1 local smoke test (production stack on localhost:8080). Run them from any machine against the public URL. You need a scan file; the synthetic one is made by pnpm --filter @dcad/web fixtures → data/synthetic/lower.stl.

B=https://dental.cognifuze.com; J=/tmp/dcad-cookies.txt; O="Origin: $B"
curl -s -o /dev/null -w '%{http_code}\n' $B/                    # 1  page → 200
curl -s $B/api/healthz                                          # 2  {"ok":true}
curl -s -c $J -H "$O" -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"a-long-password!","name":"You"}' \
  $B/api/auth/sign-up/email -o /dev/null -w '%{http_code}\n'    # 3  sign-up → 200
curl -s -b $J $B/api/me                                         # 4  {userId, orgId, role:"owner"}
CASE=$(curl -s -b $J -H "$O" -H 'Content-Type: application/json' \
  -d '{"setup":{"patientRef":"P-001","teeth":[{"fdi":36,"restoration":"anatomic-crown","material":"zirconia"}],"notes":""}}' \
  $B/api/cases)                                                 # 5  case created (201)
ID=$(echo "$CASE" | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
SHA=$(shasum -a 256 lower.stl | cut -d' ' -f1); gzip -c lower.stl > lower.stl.gz
curl -s -b $J -H "$O" --data-binary @lower.stl.gz \
  "$B/api/cases/$ID/files?kind=lower&name=lower.stl&sha256=$SHA&encoding=gzip"   # 6  upload → 201 CaseFile
FID=$(curl -s -b $J $B/api/cases/$ID | python3 -c 'import sys,json;print(json.load(sys.stdin)["files"][0]["id"])')
curl -s -b $J --compressed $B/api/files/$FID -o back.stl
shasum -a 256 back.stl                                          # 7  must equal $SHA
curl -s -b $J -H "$O" --data-binary @lower.stl.gz -o /dev/null -w '%{http_code}\n' \
  "$B/api/cases/$ID/files?kind=upper&name=x.stl&sha256=$(printf '0%.0s' {1..64})&encoding=gzip"  # 8  → 422
curl -s -b $J -H "$O" -H 'Content-Type: application/json' \
  -d '{"purpose":"agent","messages":[{"role":"user","content":[{"type":"text","text":"hello"}]}]}' \
  $B/api/llm/messages                                           # 9  LlmResponse
curl -s -o /dev/null -w '%{http_code}\n' $B/api/cases           # 10 no cookie → 401

Operations

Logs and day-to-day commands

./infra/compose.sh ps                               # status and health
./infra/compose.sh logs -f api                      # JSON logs (pino) with requestId, userId, orgId
./infra/compose.sh exec api node dist/migrate.js    # run migrations manually
git pull && ./infra/compose.sh up -d --build        # deploy a new version on the VM
./infra/compose.sh down                             # stop; volumes are kept

Every API response carries an X-Request-Id header. Search the logs for it to trace a single request.

Backups

Planned · Day 5 A backup container (nightly pg_dump + a blob volume tarball, shipped off-box to an S3-compatible target) is in the plan but not built. Until then, run these manually from ~/dcad, writing outside the deploy directory:

mkdir -p ~/backups
./infra/compose.sh exec -T db pg_dump -U dcad -Fc dcad > ~/backups/dcad-$(date +%F).dump
docker run --rm -v dcad_blobs:/blobs -v ~/backups:/out alpine tar czf /out/blobs-$(date +%F).tgz -C /blobs .

Copy both files off the VM (e.g. to OCI Object Storage). Restore: pg_restore -U dcad -d dcad --clean into the db container, and untar into the dcad_blobs volume. A restore drill onto a fresh stack is part of the planned verification (see Testing & verification).

Troubleshooting

SymptomLikely cause and fix
network shared_net declared as external, but could not be foundCreate it once: docker network create shared_net.
502 from NPMNPM is not on shared_net, or proxy is not running (./infra/compose.sh ps). Check with docker network inspect shared_net.
API exits with Invalid configurationThe zod config check failed (e.g. AUTH_SECRET shorter than 32, or BLOB_DRIVER=s3 without bucket or keys). Every bad key is listed in the log.
413 on scan uploadSet client_max_body_size in the NPM proxy host's Advanced tab and/or raise MAX_UPLOAD_BYTES.
Invalid origin / sign-in failsPUBLIC_URL must match the browser's scheme + host. Add dev origins to TRUSTED_ORIGINS.
Upload is slow, or memory grows in NPMCheck the proxy_request_buffering off / proxy_buffering off lines in the NPM Advanced tab.
LLM answers come from mockNo key was picked up. Check .env and the llm route lines in the API startup log.
429 from /api/llm/messagesPer-user limit (LLM_RATE_LIMIT_PER_MIN, default 30/min). Honour Retry-After.
Postgres auth fails after changing POSTGRES_PASSWORDThe data volume keeps the original password. Change it with ALTER USER inside the database, or recreate the volume (data loss).

Migration path

Everything speaks open protocols (SQL, the S3 API, HTTP), so moving off this VM is a configuration change plus data copy. It does not require changing app code.

DatabasePostgres 17 containerAny managed Postgres (OCI, RDS, Cloud SQL…)DATABASE_URL + pg_dump/pg_restore
Filesfs volume dcad_blobsOCI Object Storage (S3 compatibility), AWS S3, Cloudflare R2, MinIOBLOB_DRIVER=s3 + S3_*; copy objects (keys are the same relative paths)

TLSNginx Proxy ManagerCloud load balancerNothing in the app
Deeper detail: switching files to OCI Object Storage
  1. Create a bucket (e.g. dcad-blobs) and a Customer Secret Key (Identity → your user → Customer secret keys).
  2. In .env: BLOB_DRIVER=s3, S3_ENDPOINT=https://<namespace>.compat.objectstorage.<region>.oraclecloud.com, S3_REGION, S3_BUCKET, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY, S3_FORCE_PATH_STYLE=true.
  3. Copy existing blobs (keys are orgs/<org>/cases/<case>/<file>), e.g. aws s3 sync /var/lib/docker/volumes/dcad_blobs/_data s3://dcad-blobs --endpoint-url "$S3_ENDPOINT".
  4. ./infra/compose.sh up -d.

The S3 adapter disables the newer default request checksums (WHEN_REQUIRED), because some S3-compatible stores, including OCI, reject them. The BlobStore contract tests run against both fs and s3 (SeaweedFS in tests), so the switch is configuration-only. It has not yet been exercised against OCI itself.

Local runs

  • Development: cp .env.example .env, then set PUBLIC_URL=http://localhost:5173, TRUSTED_ORIGINS=http://localhost:5173, a DATABASE_URL matching POSTGRES_PASSWORD, and AUTH_SECRET. Then run ./infra/compose.sh -f infra/docker-compose.dev.yml up -d db (Postgres on 127.0.0.1:5432), pnpm dev:api (:3000) and pnpm dev:web (:5173, proxies /api).
  • Production-like: with PUBLIC_URL=http://localhost:8080 in .env (and docker network create shared_net once), run ./infra/compose.sh -f infra/docker-compose.dev.yml up -d --build. The dev override publishes the proxy on 127.0.0.1:8080; open http://localhost:8080.
  • Integration tests: pnpm --filter @dcad/api test:infra starts infra/docker-compose.test.yml (Postgres on 127.0.0.1:55432, SeaweedFS S3 on 127.0.0.1:58333, both on tmpfs), runs all tests, and tears it down.
