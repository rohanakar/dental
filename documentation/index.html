DentalCAD

A browser-based dental CAD, modelled on exocad, that designs a single posterior crown on a prepared tooth from an intraoral scan. It is designed so AI assist (Dentbird-style one-click crowns, plain-language edits, prescription intake) can plug in without a rewrite.

In short
  • What: import scans → trace the margin → get a proposed crown → adjust it → export a watertight STL for milling. All of it runs in the browser.
  • Why this slice: single crowns and short bridges are most of a lab's daily work. Doing the crown path well covers the most real use (the 80:20).
  • AI's role: LLMs (Claude / OpenAI) orchestrate and interpret. Deterministic geometry now, and specialised 3D models later, do the geometry. Both sit behind one contract.
  • Hosting: self-hosted on an OCI VM (arm64) at dental.cognifuze.com, with no vendor lock-in. Every external system sits behind a swappable adapter.
  • Status: Day 1 of a one-week MVP is done: shared contracts, scan import and viewer, backend, and deployment stack. The design steps (margin → crown → STL) arrive on Days 2–5 and AI on Day 6.
This is a prototypeA one-week build produces a working demo, not a clinical product. Use de-identified data only. Dental CAD used on real patients is a regulated medical device (FDA 510(k), EU MDR).

Five decisions that shape everything

  1. Every change is a typed command on a typed document. The UI, the auto-design orchestrator and the LLM agent share one path, so undo, replay, audit and AI safety come built in.
  2. LLMs never touch geometry directly. They call the same clinical commands a user can ("move crown 0.2 mm mesial"), and every agent change is previewed and revertible.
  3. AI plugs in through one contract. A Proposer is an async, versioned job, whether it's a browser algorithm today or a GPU model tomorrow.
  4. Geometry runs in the browser. Web Workers handle the heavy work, so the VM stays small and interaction stays fast.
  5. The backend is portable by construction. It only uses open protocols (SQL, S3 API, HTTP). Moving to managed services changes config, not code.

Full reasoning, alternatives and consequences are in the decision log.
