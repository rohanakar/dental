Product and AI

001 · MVP = single posterior crown on a natural prep

Accepted 2026-10-03
Context
One week with Claude plus one developer. Single crowns and short bridges are most of a lab's volume, and every other restoration reuses the crown's building blocks.
Decision
Build the full single-crown path for premolars and molars only, from scans to a watertight STL.
Alternatives
Broader feature coverage at lower depth (would demo poorly); anterior teeth (aesthetics-heavy, harder to judge); implants (needs library licensing).
Consequences
Preps can be assumed star-shaped from above (this simplifies intaglio meshing). Bridges and implants are the first post-MVP items.

002 · LLMs orchestrate; deterministic geometry and specialised models do geometry

Accepted 2026-10-03
Context
The user planned to use Claude/OpenAI for AI features. General LLMs cannot produce clinical-precision geometry (about 0.05 mm) from meshes with around a million triangles. Dentbird-style systems use specialised 3D networks.
Decision
LLMs handle orchestration, Rx extraction, explaining metrics, and translating plain-language edits into commands. Geometry comes from classical algorithms now, and from specialised models trained on the 100 in-house cases plus logged corrections later.
Alternatives
Vision LLM on screenshots to place margins (too imprecise); train models first (no week-1 budget, and the data is too thin).
Consequences
The Proposer contract (007) and correction logging are built from day one so models can replace algorithms step by step.

007 · Proposers are async, versioned jobs; orchestrator gated on QA checks

Accepted contract built Day 1 · runtime Day 6
Context
The same step may be served by a browser algorithm today and a GPU model tomorrow. Classical algorithms have no calibrated confidence score.
Decision
Every proposer is a job (jobId, progress, cancel) whose result carries proposerId@version, an optional model hash and deterministic QaChecks. Inputs are content-addressed meshes with explicit frame and units. The one-click orchestrator continues only when the QA checks pass.
Alternatives
A synchronous function interface (blocks remote models); gating on confidence (meaningless for classical algorithms).
Consequences
A Python ML service can implement the same contract over HTTP, and every result is traceable to the exact algorithm or model version.

008 · LLM tool loop runs in the browser; API is a keyed proxy

Accepted supersedes S3
Context
The tools need geometry, metrics, view capture and preview, and those live in the browser. A server-side loop would need two-way tool messaging back to the client.
Decision
The browser runs the loop and calls POST /api/llm/messages. The server holds keys, picks provider and model, enforces an allowlist and rate limit, and logs usage. Tools are clinical and tooth-local (move_crown {direction, mm}), and every agent batch is one transaction with Accept/Revert.
Consequences
About a day of plumbing saved; the agent can never bypass command validation; the proxy is provider-agnostic.

006 · Crown is a union: template or mesh

Accepted
Decision
{kind:'template', templateId, pose, deltas?} | {kind:'mesh', mesh}.
Why
A crown produced by an ML model is an arbitrary mesh and can't be expressed as a deformed template. Without the union, the document couldn't hold future AI output.

Frontend

003 · React + TypeScript + plain three.js

Accepted
Decision
React for panels; an imperative three.js Viewer class (not react-three-fiber); three-mesh-bvh for picking and distance queries; camera-controls for navigation.
Alternatives
react-three-fiber (less control over render-on-demand and buffer updates); Babylon.js (good tooling, but no equivalent of three-mesh-bvh).
Consequences
React talks to the engine through a small API; the engine stays testable and framework-free.

004 · Geometry in Web Workers; BVH built in the worker and serialized

Accepted built Day 1
Context
Scans have 200k–1M+ triangles. three-mesh-bvh reorders the index buffer when it builds (unless indirect: true), so face ids taken earlier become wrong.
Decision
Build the BVH once in the worker, ship it with MeshBVH.serialize, and deserialize it on the main thread so the reordered index is canonical. Always transfer buffers. Use "latest wins" generation counters because Comlink can't cancel calls. Store margins as 3D points, not face ids.
Consequences
Measured: a 1M-triangle STL takes about 0.5 s total in Node and is usable in about 1 s in the browser.

005 · Typed commands on a typed document; undo via immutable snapshots

Accepted, Day 4 supersedes S4
Decision
All state changes are zod-validated Commands. Undo is a stack of immutable document snapshots with structural sharing, plus a derived-geometry cache keyed by input hashes. Changing a step marks the later ones stale.
Alternatives
A hand-written invert() per command (about 20 inverses to write and keep correct).
Consequences
An agent batch is one version; replay and provenance come free; sculpt deltas live in the crown's local frame so they survive re-fits.

020 · Step status map is exhaustive

Accepted
Context
In zod v4, z.record(StepId, StepStatus) requires every enum key.
Decision
Keep it exhaustive (every tooth tracks all nine steps) and create maps with initialSteps().

Geometry

013 · Intaglio via normal offset + ray-cast envelope + radial meshing

Accepted, Day 3 supersedes S1
Decision
Offset prep vertices along smoothed normals by a gap profile gap(d) (0 at the margin, ramping to the cement gap, plus the extra spacer beyond "distance to margin"). Take the upper envelope by ray-casting along the insertion axis, which also blocks out undercuts. Mesh it with radial profiles from each margin point toward the prep centre, resampled by arc length.
Consequences
The gap is correct on steep axial walls; the boundary is exactly the margin points (simple stitching); no triangulation library is needed. It requires a star-shaped projected margin, which is checked and warned about.

014 · Tool-radius compensation left to CAM

Accepted, Day 3
Context
Dilating the whole intaglio by the tool radius (0.3–0.5 mm) would make every crown loose. Relief is only needed at sharp convex prep edges.
Decision
No compensation by default. Show an "unmillable" map (a morphological opening with the tool radius). Local relief domes are a stretch goal.

015 · Eight hand-annotated template teeth

Accepted, Day 2–3
Context
Mining a library from 100 cases hides days of work: splitting outer from inner surfaces, and canonical frames.
Decision
Four posterior types × two jaws, mirrored for the other side (with flipped winding). Each cervical loop is resampled to a fixed N offline and matched to the margin by normalised arc length from a mesial start with enforced winding. RBF deformation with anchors on the occlusal third.
Consequences
Angle-based loop matching (which can twist the strip silently) is avoided; anatomy variety is limited until a learned generator exists.

Backend and infrastructure

009 · Self-hosted portable backend on OCI; Supabase dropped

Accepted supersedes S2
Context
The user wants to move between providers easily and already has an OCI VM (12 vCPU, 6 GB RAM, Docker, HTTPS).
Decision
Node + Hono API with ports and adapters; Postgres, Caddy and the API in Docker Compose with memory limits; only open protocols.
Consequences
Moving to managed Postgres, S3, OIDC or Kubernetes is a config or adapter change (see the migration table in Deployment). We operate backups ourselves.

010 · Better Auth in our own Postgres, behind AuthPort

Accepted
Decision
Better Auth (a TypeScript library) with the organisation plugin; its tables are generated into our Drizzle migration; each new user gets a personal organisation.
Alternatives
Keycloak (heavy on 6 GB of RAM); a hosted IdP (lock-in); hand-rolled JWTs (security risk).
Consequences
Swapping to an external OIDC provider means replacing one adapter. Gotcha: Better Auth ignores its base-path option when the URL has a path, so the adapter sets the full URL and re-adds the sub-path.

011 · Blob storage: fs by default, S3 adapter ready; uploads stream through the API

Accepted
Decision
A BlobStore port with fs (Docker volume) and s3 (any S3-compatible service) adapters. Uploads stream through the API with the size cap and sha256 enforced while streaming; gzip is decompressed only for hashing.
Alternatives
Presigned direct uploads (faster at scale, but tied to each provider's presign behaviour).
Consequences
Same contract test suite for both adapters. Measured: a 150 MB upload kept the API at about 112 MiB.

012 · Postgres + Drizzle with committed SQL migrations; no Redis

Accepted
Decision
Drizzle schema → generated plain-SQL migrations under apps/api/drizzle/, run on start. Background jobs, when needed, use pg-boss on the same Postgres.
Consequences
One stateful service to back up; any managed Postgres works.

016 · Public URL is configurable; dental.cognifuze.com at root

Accepted replaces the earlier choice of cognifuze.com/dental
Decision
PUBLIC_URL drives everything. Sub-path mounting still works if BASE_PATH / VITE_BASE_PATH are set by hand (Caddy strips the prefix). Since 2026-10-11 the deployment sits behind Nginx Proxy Manager, which reaches our Caddy as dcad-proxy:80 on the external Docker network shared_net.

017 · arm64 container images

Accepted
Decision
The VM is aarch64, so images are built natively for linux/arm64 (node:22-slim, postgres:17, caddy:2).

018 · SeaweedFS for S3 contract tests

Accepted Deviation from plan
Context
The plan named MinIO, but the minio/minio image is no longer on Docker Hub.
Decision
Run the S3 adapter's contract tests against SeaweedFS. The production S3 adapter is unchanged.

019 · Shared package consumed as TypeScript source

Accepted
Decision
@dcad/shared exports src/index.ts directly; Vite compiles it for the web and tsup bundles it into the API build.
Consequences
No build step or project references to maintain; imports are extensionless (bundler resolution).

Superseded

S1 · Heightfield intaglio with spherical dilation

Superseded by 013

The first draft rasterised the prep along the insertion axis at 0.05 mm and applied cement gap and tool radius by spherical dilation. Review found that a 0.02–0.04 mm gap sphere is smaller than one grid cell, so the dilation degenerates to a vertical shift. On a 5° axial wall that yields an effective gap of only about 0.04 × sin 5° ≈ 0.003 mm, and the crown would not seat. Dilating by the tool radius would also over-cut the entire intaglio.

S2 · Supabase for auth, database and storage

Superseded by 009

Chosen first for speed. Dropped at the user's request for easy migration, and because their own VM was available. Supabase's free-tier 50 MB file cap would also have clashed with 50 MB+ scans.

S3 · Server-side LLM tool loop

Superseded by 008

Would have required streaming tool calls back to the browser, where geometry and preview live.

S4 · Hand-written invert() per command

Superseded by 005

Error-prone and about 20 inverses to write. Snapshots make undo, agent batches and replay uniform.
