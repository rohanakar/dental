Testing & verification

What is tested today, how to run it, what was measured, and what still has to be proven before the crown pipeline can be trusted.

In short
  • 70 automated tests, all passing (2026-10-03): 52 unit tests (shared 6, web 28, API 18) plus 18 API integration tests against real Postgres and S3-compatible storage in Docker.
  • A 1M-triangle scan parses, cleans, welds and gets its BVH in 438 ms in Node (measured; the soft limit is 5 s).
  • The production Docker stack passed a 10-check end-to-end smoke test locally: sign-up → case → 50 MB scan upload → identical download → mock LLM.
  • Not yet tested because not yet built: the crown geometry (margin, intaglio, fit, adapt, export) and the AI loop. They are verified by planned invariant tests and a golden-case regression against real exocad crowns, which needs 3–5 cases from you.
  • There is no CI yet. Tests run locally with pnpm.

Test pyramid

Fast tests at the bottom run on every change. Slower ones at the top prove the parts work together and against real data.

Kinds of tests, in plain terms

Geometry and infrastructure code is tested differently from typical CRUD code. The outputs are big arrays, and "correct" is often a property ("closed", "nothing thinner than 0.5 mm") rather than one exact value. These are the kinds of tests in the repo today, each with a real example.

KindWhat it meansReal examples (test names)Why we use it
Hand-made inputBuild a tiny input in the test (a few bytes or triangles) where the right answer is obvious.stl.test.ts: "welds a cube soup into 8 vertices and 12 faces"; ply.test.ts: "parses ASCII PLY with colors and triangulates quads"; cleanup.test.ts: "removes faces with repeated indices and zero area"Pin down each rule of a parser or algorithm.
Edge cases from real-world filesInputs that broke other software or arrive from odd scanners."detects binary STL whose header starts with 'solid'"; "treats -0 and +0 as the same vertex"; "parses binary big-endian PLY with double coordinates, float colors and extra properties"; "rejects faces that reference missing vertices"Scanner exports vary, and these bugs are silent: wrong geometry, no crash.
Round tripWrite, then read back (or send, then receive), and check nothing changed."round-trips binary STL"; "round-trips binary little-endian PLY with colors"; scanPayload.test.ts: "serializes the BVH in the worker and rebuilds it on the main thread" (the same ray hits the same triangle)Catches asymmetric bugs between writer and reader, and between the worker and main thread.
Geometric propertyAssert a mathematical fact instead of exact numbers."computes +z normals for a flat grid"; "weights by face area"; "finds the occlusal-plane normal of an arch as the least-variance axis"; "diagonalizes a symmetric matrix"Robust to harmless changes like vertex order or float noise.
Synthetic dataGenerated jaws (the same as the demo, with a prep on tooth 36) instead of patient scans."imports a synthetic arch STL without warnings"; "estimates a view frame for the synthetic jaws"; "warns when units look wrong" (the same jaw scaled ×1000 and ÷1000, as if exported in microns or metres)Realistic size and shape, with no patient data in the repo.
Behaviour of small helpersPlain logic tests for non-geometry code.files.test.ts: "detects roles from common export names", "normalizes VITE_BASE_PATH"; "discards superseded results" (latest wins); shared.test.ts: tool schemas and FDI validationCheap, fast, and these rules are easy to break.
Performance budgetRun at full size and fail if it's too slow."processes and builds the BVH for a ~1M-triangle STL" (soft limit 5 s; measured about 0.44 s)Speed is a feature here; regressions show up immediately.
Contract testOne suite run against every implementation of an interface.blob-store.contract.test.ts runs the same 5 tests on the local-disk and S3 stores: "round-trips a streamed object", "returns null for missing objects", "overwrites", "deletes idempotently", "rejects a failing upload stream and stores nothing"Proves the backends are interchangeable, which is the point of the portable design.
Security checkTry to break a boundary."rejects keys that escape the root" (path traversal on the disk store); "isolates organizations" (another lab's case returns 404)Tenancy and file-system safety must never regress.
Translation (no network)Check our format converts correctly to and from each provider's API, without calling it.llm-adapters.test.ts: "maps provider-agnostic messages and tools to the Messages API"; "turns optional properties into required nullable ones" (OpenAI strict mode); "normalises every agent tool schema"Free, fast and deterministic; provider quirks are captured once.
ConfigurationEnv vars in, chosen behaviour out."falls back to mock without keys"; "prefers anthropic, then openai"; "derives the base path from PUBLIC_URL"Deployment mistakes become test failures, not outages.
Integration (real infrastructure)The real HTTP app against real Postgres and real S3-compatible storage in Docker; no mocks.api.integration.test.ts: "signs up into a personal organization", "uploads gzip with streaming sha256 verification and downloads it back", "rejects sha256 mismatch, invalid gzip and oversize uploads without leaving blobs", "saves versions with optimistic concurrency", "accepts proxy-stripped auth requests and scopes cookies to the sub-path"SQL, auth cookies, streams and migrations behave differently from mocks.
Smoke test (manual, scripted)curl against the full production Docker stack.10 checks on 2026-10-03 (see below)Proves images, Caddy routing, env and migrations work together.
Coming with the crown pipeline
  • Invariant tests on every geometry step, e.g. "the exported crown is closed", "no triangle crosses another", "the inner surface is 0.04 mm ± 0.01 from the prep measured along the normal".
  • Golden-case regression: run real de-identified cases headlessly and compare our crown to the exocad crown by Hausdorff distance.
  • Browser end-to-end tests with Playwright, and mocked-LLM tests for the agent loop.
Details are in Planned verification.

How to run

# once per machine (works around a corepack signing-key bug on this Node version)
export COREPACK_INTEGRITY_KEYS=0
corepack enable
pnpm install

pnpm test                                  # all unit tests (integration suites skip)
pnpm typecheck                             # TypeScript 7, every package
pnpm --filter @dcad/web test               # web only
pnpm --filter @dcad/shared test            # shared schemas only
pnpm --filter @dcad/api test               # API unit tests
pnpm --filter @dcad/api test:infra         # API unit + integration (starts/stops Docker)
pnpm --filter @dcad/web fixtures           # write synthetic scans to data/synthetic/

The integration harness

test:infra runs apps/api/scripts/test-infra.sh, which:

ServiceImageHost portNotes
Postgrespostgres:17127.0.0.1:55432Data on tmpfs (nothing persists); database dcad_test.
S3-compatible storechrislusf/seaweedfs127.0.0.1:58333Data on tmpfs; test credentials defined inline in the compose file.

The ports are non-default, so the harness can run next to a local dev database. Integration suites use describe.skipIf(!TEST_INFRA), which is why they show as skipped in a plain pnpm test.

DeviationDeviation The plan named MinIO for S3 tests, but the minio/minio image is no longer published on Docker Hub. SeaweedFS speaks the same S3 API. Production storage is unaffected: the app uses the filesystem adapter by default and any S3-compatible service via BLOB_DRIVER=s3.

Performance

The import pipeline has a performance test in apps/web/src/workers/scanPayload.test.ts. It runs the full pipeline plus BVH build on a synthetic ~1M-triangle binary STL (50 MB) in Node, logs the timings and soft-asserts < 5 s.

StageMeasured (Node, Apple Silicon arm64, 2026-10-03)
Parse13 ms
Weld (exact float-bit)60 ms
Cleanup49 ms
Normals27 ms
Process total (incl. sha256)176 ms
BVH build261 ms
Total438 ms (an earlier run measured 467 ms)

In the browser (headless Chrome, measured informally while building Day 1), the 1M-triangle lower plus 300k-triangle upper demo scans were ready about 0.8–1 s after the click. The API side was checked by hand: a 150 MB upload took about 1.1 s while the API process stayed near 112 MiB, so uploads are streamed, not buffered. A 210 MB upload was refused with 413.

Planned verification

Most of the product risk is in the geometry, which is not built yet. Each planned item is listed with when it lands.

Geometry invariants (unit) Planned · Day 2–5

ComponentInvariant the test asserts
Live-wire marginPath is continuous along mesh edges between anchors; the loop closes.
Intaglio (inner surface)Cement gap measured along the surface normal on the axial walls is within ±0.01 mm of the target; no undercut (every ray along the insertion axis hits once).
Crown solidClosed manifold (every edge has two faces), consistent orientation, signed volume > 0, no triangle–triangle intersections.
ThicknessOuter-to-intaglio distance ≥ the thickness profile everywhere (margin thickness at the margin, material minimum beyond).
UndoSnapshot undo/redo round-trips; editing an upstream step marks downstream steps stale.

Golden-case regression (headless) Planned · Day 2–7

The backbone of geometry testing. A headless runner (tools/pipeline-runner) loads each golden case, places the margin from stored points, runs axis → intaglio → fit → adapt → export, and writes the STL and a metrics JSON. The metrics are compared with the crown the lab actually made in exocad.

Golden cases needed

Synthetic scans (pnpm --filter @dcad/web fixtures) are enough for import and viewer tests, but not for margins or crown fit. Those need real preps. Please provide 3–5 de-identified cases from the ~100 in-house cases:

ItemRequired?Why
Prep jaw scan (STL or PLY)YesMargin, axis and intaglio are computed on it.
Opposing jaw scanYesOcclusal clearance and adapt-to-antagonist.
Scans exported in occlusion (common coordinates)YesAutomatic bite alignment is out of MVP scope.
Finished crown STL from exocadStrongly preferredReference for the Hausdorff regression.
exocad project files (.dentalProject, .constructionInfo)If availableGround-truth margin line and insertion axis.
Pre-op scanOptionalUseful later for copy-mode.
  • Mix: single posterior crowns (premolars and molars), both jaws, at least one zirconia and one lithium disilicate.
  • Where: data/golden/<case-id>/ in the repo. data/ is gitignored, so scans never reach git.
  • Privacy: strip patient names from file names and metadata; use a pseudonymous case id.
