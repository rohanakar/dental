# Margins that fix themselves: a refiner, margin tools for the model, a prep check, and a local Opus 5.5

Status: **in progress** (2026-10-26). Branch `margin-ai`.

## Goal

The user (2026-10-26), after the one-click margin failures (`2026-10-26-no-prep-no-crown.md`) and a look at how
exocad, 3Shape Automate and Dentbird work:
- "a vision-LLM 'does this tooth look prepared?' check: which models are there for this?"
- "What if we provide tools for correcting margins, so that the margin detection can make around 10 tool calls for
  the best fit?"
- "Work on it in a separate branch … we will simulate Opus 5.5 using `claude -p` (I believe we can do it with a mock
  Docker image)."

On a prepared tooth whose automatic margin fails its checks, the margin should be repaired by deterministic code
first, then by a model that can look at the prep and use a small set of margin tools within a bounded number of
calls. On a tooth that may not be prepared, a model can give a second opinion. Development and evaluation run
against Opus 5.5 through the local `claude -p`, with no API key in the app.

## Ground rules

- **Geometry is computed, never generated.** PRODUCT.md: "LLMs orchestrate and explain. They never produce clinical
  geometry." Every tool is a deterministic operation on the scan: snap an anchor to the finish line, re-trace one
  side with the live-wire, smooth, or re-run the automatic margin with other settings. The model only chooses which
  tool to call and where. The margin checks (`ai/qa.ts` `marginGate`) judge every result.
- **Drafts:** everything a model does is a draft (one undo step, Accept or Reject), as with the design assistant.
- **Data:** only synthetic or de-identified data. The bridge sends what the app sends (renders and numbers of the
  synthetic case) to Anthropic through `claude -p`.

## Scope

**In:**
1. **Refiner (no model).** A bounded local search that repairs an automatic margin that failed its checks. It tries
   more profiles (16 → 24 → 32), snaps anchors to the finish line within a small radius, drops the anchors behind
   each kink and re-traces, and smooths. It keeps the best-scoring margin by the gate. The margin proposer runs it
   before reporting a failure.
2. **Margin tools** for a model, shared by the in-app assistant and the headless harness:
   - read: `get_margin_report`, `render_margin_view`;
   - edit: `add_anchor`, `remove_anchor`, `move_anchor`, `retrace_side`, `smooth_side`, `rerun_auto_margin`;
   - judge: `check_margin`.

   It has a budget of 10 calls and stops when the gate passes.
3. **Prep check (vision).** Renders of the tooth (occlusal and buccal, with the tooth number), and the question
   "is this tooth prepared for a crown?". The answer is yes, no or unsure, with one line why. It is advisory, shown
   beside the prep finder, never a gate.
4. **A local Opus 5.5 (`tools/claude-bridge`).**
   - **What it is:** a small HTTP server that speaks the Anthropic Messages API (`POST /v1/messages`: system,
     messages with text, image, `tool_use` and `tool_result` blocks, tools).
   - **How it answers:** each request becomes one `claude -p --model claude-opus-5-5 --tools "" --json-schema …
     --output-format json` call. Images go in through `--input-format stream-json`.
   - **What it returns:** a `tool_use` or text block.
   - **Running it:**
     - the app's Anthropic adapter is pointed at it with `ANTHROPIC_BASE_URL`;
     - on the host it uses the local `claude` login;
     - a Dockerfile runs it in a container with `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`).
5. **Evaluation harness** (`tools/pipeline-runner`, a `margin-eval` command). Cases are synthetic prepped teeth whose
   automatic margin is made to fail on purpose:
   - a scan with noise;
   - a frame off the prep top;
   - a margin seeded with wrong anchors;
   - a natural tooth, the negative control.

   For each case it runs the plain margin, the refiner, and the refiner plus the model loop (through the bridge). It
   reports pass rate, deviation from the true margin (`syntheticPrepMargin`), calls, time and cost.

**Out:**
- Training a 3D model (the 3Shape and Dentbird way). That is a separate project that needs real data.
- Margins on natural teeth: the negative control must stay a failure, or come back as "not a prep".
- Production deployment of the bridge. It is a development tool. Production uses the API adapters with real keys.

## Design

### 1. Refiner (`geometry/marginRefine.ts`, worker `refineMargin`)
- **Input:** the scan, the frame, the failed trace, and the gate.
- **Candidates,** each re-traced with `marginFromAnchors` and scored by the gate (a pass beats a fail; then the
  sharpest bend, then the length's distance from the anchor ring's perimeter):
  1. `proposeMarginAnchors` with 24 and 32 profiles;
  2. each anchor snapped to the strongest curvature ridge within 0.6 mm along its profile;
  3. for each kink, the anchors on either side dropped and the side re-traced;
  4. a light smooth of the trace.
- **Bounds:** at most about 12 traces, under 1 s on the demo arch.
- **Margin proposer:** `classical.margin-ridge` calls it when the plain trace fails, and reports which candidate won
  in its rationale.

### 2. Margin tools (`packages/shared/src/marginTools.ts` definitions; `geometry/marginTools.ts` operations)
- **Pure functions over** `{ scan, frame, margin: { anchors, points } }`, returning a new margin and its report. They
  are the same functions in the worker (in the app) and in Node (the harness).
- **The report:** length, sharpest bend and where (side and anchor index), finish-line share per side, anchors
  (index, side, position), and the gate.
- **The render** (`render_margin_view`): app only; the harness renders the same view with a small offscreen
  rasteriser, or sends no image in its first version.
- **In the app:** the assistant gets the tools for the Margin step. A "Fix the margin with AI" action on a failed
  margin runs at most 10 calls inside a draft.

### 3. Prep check (`ai/prepCheck.ts`)
- **Asks:** two `capture_view` renders of the active tooth, plus a structured question with the answer
  `{ prepared: 'yes'|'no'|'unsure', why }`.
- **When:** on Tooth frame when the prep finder found no prep for a crown tooth, or on demand. Its answer appears in
  the status line next to the finder's.

### 4. Bridge (`tools/claude-bridge`)
- **Server:** Node 22, no framework, `POST /v1/messages` and `GET /health`.
- **Prompt:** the system prompt plus a transcript of the messages. Tool results appear as text; images are passed as
  image content blocks through `--input-format stream-json`.
- **Decision:** `--json-schema` for `{ kind: 'tool_use'|'text', name?, input?, text? }`. The input is checked against
  the named tool's schema, and an invalid answer is retried once.
- **Response:** Anthropic's shape (`id`, `model`, `content`, `stop_reason`, `usage` with zeros), so the SDK accepts
  it.
- **Concurrency:** one `claude -p` at a time per request, with a small queue. Logs go to stderr.
- **Docker:** `node:22-slim`, `npm i -g @anthropic-ai/claude-code`, non-root, reading `CLAUDE_CODE_OAUTH_TOKEN`.
  `docker compose --profile claude-bridge up` in `infra/` for development.

### 5. Harness (`tools/pipeline-runner/src/marginEval.ts`, `pnpm --filter @dcad/pipeline-runner run margin-eval`)
- Builds the cases above at the demo resolution and runs the three variants.
- Writes a table (pass, deviation, calls, ms, cost) to stdout and `out/margin-eval/`.
- The model variant needs `ANTHROPIC_BASE_URL` (the bridge) or skips with a note.

## Bridge: implementation summary

**Built** (scope item 4, design §4): `tools/claude-bridge`, the workspace package `@dcad/claude-bridge`. It is a
plain `node:http` server with no runtime dependencies, run with `node --experimental-strip-types` (`pnpm --filter
@dcad/claude-bridge start`, port 8787).
- `src/prompt.ts`: request checks; the prompt; the decision schema; the decision check.
- `src/schema.ts`: a small structural JSON Schema check for tool inputs (type, enum, const, required, properties,
  `additionalProperties`, items, bounds, `anyOf`/`oneOf`/`allOf`, local `$ref`). The repo has no ajv.
- `src/claude.ts`: one `claude -p` run.
- `src/server.ts`: `POST /v1/messages`, `GET /health`, the queue (`CLAUDE_BRIDGE_CONCURRENCY`, default 1).
- `Dockerfile`, a `claude-bridge` service under the `claude-bridge` profile in `infra/docker-compose.dev.yml`, and
  `README.md`.

**Deviations and decisions:**
- `--input-format stream-json` needs `--output-format stream-json --verbose`. The bridge reads the last `result` line
  (`is_error`, `structured_output`, `total_cost_usd`, `duration_ms`).
- **Settings:** claude also runs with `--safe-mode`, which turns off CLAUDE.md, skills, plugins, hooks and MCP but keeps
  the OAuth login (unlike `--bare`). The request's system prompt replaces Claude Code's own through `--system-prompt`.
  A call is about 1.2k input tokens, which brings the cost from about $0.03 to about $0.01.
- **Prompt:** the tools, the transcript (tool calls and results as `<tool_call>`/`<tool_result>` text, images in
  place) and the instructions go in one stream-json user message.
- **Retries:** an invalid answer is retried once, with the reasons. Claude's `error_max_structured_output_retries`
  counts as an invalid answer. Any other CLI error is a 502, and a timeout (`CLAUDE_BRIDGE_TIMEOUT_MS`, 180 s) is a
  504. Every 5xx carries `x-should-retry: false`, so the SDK's own two retries don't triple a paid call.
- **Headers and choices:** besides `x-bridge-cost-usd` and `x-bridge-ms`, replies carry `x-bridge-attempts`.
  `tool_choice` (`auto`/`any`/`tool`/`none`) is honoured. `stream: true` and non-`claude-*` models are a 400.
- **Environment:** claude's environment has no `ANTHROPIC_BASE_URL`, no `ANTHROPIC_API_KEY=bridge` and no empty
  credentials, so it never calls the bridge.
- **No API change:** the Anthropic SDK reads `ANTHROPIC_BASE_URL` itself.

**Verification:**
- `pnpm typecheck` passes. `pnpm test`: 116 tests, 104 passed and 12 skipped (+1). The new test is
  `tools/claude-bridge/src/bridge.test.ts`.
  - It stubs `claude`: through the real SDK, a request with a tool, an image and a `tool_use`/`tool_result` history
    makes one `claude -p` run in the empty cwd. The run carries the system prompt, the tool schema, the transcript
    and the image block.
  - An invalid first answer (a `side` outside the enum) is retried with the reason, and the answer comes back as a
    `tool_use` with the cost of both runs.
  - A CLI error is a 502 that the SDK does not retry.
- **Live, 2 calls to Opus 5.5 on the host:**
  - **The SDK with a tool and a 64 px PNG:** `tool_use record_disc {colour: "green", fdi: 36}`, in 3.7 s end to end
    (2.2 s in claude), for $0.0137.
  - **The API's own `AnthropicProvider`,** pointed at the bridge only by `ANTHROPIC_BASE_URL`, on the turn after a
    `tool_result`: a text answer in 3.8 s, for $0.0090.
- **Docker:** the image builds on arm64 (claude 2.1.310, user `node`), and `/health` answers. With no token, a request
  is a 502 ("Not logged in"). The compose service resolves under its profile.

**Follow-ups:**
- The container is not yet tested with a real `CLAUDE_CODE_OAUTH_TOKEN`.
- `usage` is always zero, so the harness should read `x-bridge-cost-usd`.
- The system prompt goes in as one argv string, and Linux caps one argument at 128 KB. That is far above the app's
  prompts.

## Implementation summary (phase 1: refiner, tools, model loop, harness)

**What was built, and where**
- **`geometry/marginShape.ts`:**
  - the gate's shape measures, moved out of `ai/qa.ts` (`sharpestTurnDeg`, `turnsDeg`);
  - limits `MARGIN_LENGTH_MM`, `MARGIN_MAX_TURN_DEG` and `MARGIN_MAX_WANDER` (1.15), where wander is the traced length
    over the perimeter of the anchor ring: a detour adds length.
- **`geometry/autoMargin.ts`:** `withCandidates` returns every strong convex edge of each profile, not only the first.
- **`geometry/marginRefine.ts`:** the refiner.
  - It runs 16, 24, 32 and 48 profiles. Its anchors are either the first edges, or the ring-consistent ones (a median
    filter), or the **ring DP**: a cyclic dynamic program that picks one edge per profile so drop and radius change
    slowly round the prep.
  - Each set is traced with and without a 0.4 mm smooth back onto the scan.
  - It keeps the best candidate: passing, then least wander, then gentlest turn. That is 14 traces, 0.2–0.7 s on the
    demo arch.
- **The app uses it:**
  - the worker's `autoMargin` returns the refiner's best, with `wander` and `method`;
  - the margin proposer passes `wander` to the gate, which gains `margin.wander` ("No detours"), and names the method
    in its rationale.
- **`geometry/synthetic.ts` `withScanNoise`:** deterministic scanner-like noise along the normals.
- **`geometry/marginTools.ts`:** the margin tools:
  - read: `marginReport` (pass, length, sharpest turn, wander, found share, kinks by side with the nearest anchor,
    anchors with height and radius, plain-language problems);
  - edit: `rerunAutoMargin`, `removeAnchor`, `addAnchor` (on the finish line, on the profile at that angle),
    `moveAnchor` (≤ 1 mm, back onto the scan), `smoothWork`;
  - `retrace`.
- **`ai/marginAgent.ts`:** the model loop.
  - Tools: `get_margin_report`, `rerun_auto_margin`, `remove_anchor`, `add_anchor`, `move_anchor`, `smooth_margin`,
    `finish(fixed | cannot_fix | not_a_prep)`.
  - It has a 10-call budget and keeps the best margin seen.
  - It is exported to Node as `@dcad/web/margin-agent`.
- **`tools/pipeline-runner/src/marginEval.ts` (`margin-eval`):**
  - 21 synthetic cases at the demo resolution, with methods `plain`, `refine`, `agent` (from the plain margin) and
    `refine+agent` (the model only when the refiner fails or looks doubtful: wander > 1.08 or kept < 0.75);
  - the client `anthropicLlm.ts` sends Messages API calls to `ANTHROPIC_BASE_URL`;
  - results go to `out/margin-eval/`.
- **`tools/claude-bridge`:** see "Bridge: implementation summary" above.

mean of the true margin; for a natural tooth, rejected.

**Deviations from the spec:**
- **The refiner always runs,** not only after a failed plain margin: the plain margin passes some wrong margins (1.7
  mm off), which only the refiner's wander catches.
- **No anchor-snapping candidate:** the ring DP over all profile edges does that job.
- **`retrace_side` and `check_margin`** became `rerun_auto_margin` and `get_margin_report`.
- **The tool definitions** live in `ai/marginAgent.ts`, not in `packages/shared`.

  - `geometry/marginTools.test.ts`: edits keep a clean margin passing, and a dragged anchor's kink is named by side;
  - the bridge test.
- **Browser scripts** `first-run`, `ai-bridge`, `crown-move` and `ai-framework` pass with the refiner in the worker.

## Phase 2a: the model inside one-click auto-design (tried, dropped)

**What was tried.** The user (2026-10-26): "When I click one-click crown (auto-design), it is not making the LLM
call." The margin step was wired to call the model loop when the refined margin failed or looked doubtful. The tools
ran in the geometry worker, and the offline dev editor reached the bridge through a Vite proxy.

**What it showed in the browser,** with Opus 5.5 through the bridge:
- **Prepped 36:** the refiner passed, so no call was made.
- **Natural 11:**
  - 9 calls and 87 s, ending with "not prepared". The refiner's wander already says that (natural teeth measure
    1.37–1.64 against a limit of 1.15).
  - The browser made 12 requests, with an unexplained 186 s stall.
  - The bridge had stopped by the end of the run.

**Decision.** The user: "I don't see this working well", then "merge that with main, remove the Opus crap". The
model adds no accuracy the refiner lacks:
- the refiner gets 16 of 17 prepped cases right;
- on the 17th, Opus was still 0.66 mm off;
- it adds minutes, cost and a fragile dependency to one-click.

The wiring was not committed. It is kept as `git stash` "margin-ai phase 2a: Opus in one-click auto-design (dropped by
the user 2026-10-26)".

**What stays:**
- the refiner, in one-click;
- the margin tools, the model loop and the bridge, as development tools for the `margin-eval` harness only. The app
  makes no model call for margins.

**Next, if anything:** a deterministic, instant "this tooth doesn't look prepared" stop (`2026-10-26-no-prep-no-crown.md`).
